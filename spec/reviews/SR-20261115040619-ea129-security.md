## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | medium | gitsign reads trust roots (gitsign.fulcioRoot etc.) from the configuration of its working directory, which for tags is now the snapshot, but the snapshot's configuration is only "a minimal configuration of its own": nothing requires it to hold no gitsign.* or include key, or forbids a git init template (init.templateDir from the caller's global config) from seeding it. FR-040-CON-1 still conditions signed_valid on "a repository" with no gitsign.* key, now ambiguous between source and snapshot. State that the snapshot is created without templates in the pinned environment and its configuration holds no gitsign.*, include or includeIf key. | spec/functional/FR-040-gitsign-sigstore-keyless-commit-and-tag-verification.md:167, 228 |

## Verdict

FAIL (one medium). Exact-object binding is sound: the snapshot holds only the resolved tag object, re-hashed to its id, with no alternates, so a source ref move/delete or config change after resolution cannot change the verified object, and every snapshot failure fails closed to unverifiable. FR-080 refuses verified for any object other than the caller's expected id however its signature and fields verify, and keeps verified distinct from FR-041 human approval. The gitsign v0.18.0 claim (ref-only, non-bare) was taken as stated, not re-measured.
