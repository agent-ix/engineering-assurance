# Code review and Rust review of the Baseline and Release archetypes (engineering-assurance PR 227)

## Summary

Ticket: EA-93. PR agent-ix/engineering-assurance#227 at head 4110edf, diff `origin/main...HEAD` (10 files, +435/-8). Code-review with the rust-review lane folded in (rust-style loaded). Checked against FR-046, FR-047, FR-050, FR-051 and NFR-007 as merged; the EA-93 ticket text was read as data.

Measured: `cargo test --features full --test semantic_exports --test manifest_parity --test python_port --test content_rights_parity` all pass (11 + 7 + 78 + 7); `cargo fmt --check` clean; `cargo clippy --features full --lib --test semantic_exports --test manifest_parity --test python_port -D warnings` clean; `cargo test --features full --test traceability_reconciliation` FAILS at head (TC-118) and the same reconciliation is clean on origin/main. Sample documents were run through the repo's validator (`quire validate --module engineering_assurance`, quire 0.44.0).

## Verdict

**FAIL** - two high findings: the PR breaks TC-118 with two trace ids that name nothing (FND-001), and FR-046's duplicate-path refusal is not met (FND-002).

Checked and clean: both schemas are closed (`additionalProperties: false` at the document, Baseline item and Release `baseline` levels); neither has a digest, hash, score, status, approval or decision member, and the Baseline has no `commit` member (tests assert the exact member sets). The path pattern refuses absolute, `..`, `.`, empty-segment, trailing-slash, empty and glob paths; measured bypass attempts are in FND-007. `snapshot_path` is required, as the merged FR-047/FR-051 say. The ticket's 'previous release' member is not in the merged FR-047 Inputs; the schema refuses `previous_release` and the spec wins (EA-103 'version history' is the place to raise it). The inventory updates (`ARTIFACTS` 7, export count 9, `module_inventory_is_exact`, `retained_bundle`) are additive and truthful, not weakened. The content-rights `SEMANTIC_EXPORT_SCHEMAS` entries are needed: the scan admits each exported schema's own `$id` URL only for listed files, and `content_rights_admits_exactly_the_manifest_data_schema_files` checks the list against the manifest. The two README artifact-type rows are accurate. Skeletons pass `quire validate --module --strict` via `quire_accepts_every_skeleton_without_diagnostics`. The refusal message names the member (`at items.0.path`, `at items`, `at items.0.kind`).
