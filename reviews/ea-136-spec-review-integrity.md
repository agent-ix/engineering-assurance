## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | medium | spec/tests.md gains 11 hand-kept rows, TC-1101..TC-1111. The owner ruled on 2026-11-23 that the Test Matrix is generated by `quoin matrix` / `quire matrix` and that hand-kept tests.md rows and TC ids are ceremony. Drop the added rows. Tests trace to the AC ids directly. | spec/tests.md:1072-1082 |
| FND-002 | medium | FR-041-AC-35 contradicts itself, and the Outputs text disagrees about `ea_version`. AC-35 says every `approval-verify` result carries `trust.allowed_signers_sha256`, then says a git failure while reading yields neither digest nor commit. The Outputs bullet places all four new members "on every result whose allowed-signers reading succeeded", yet its parenthesis names only the digest and commit as absent on `git_failed`. AC-35 and FR-043-AC-26 say `ea_version` is on every result. Say once whether `ea_version` appears on a `git_failed` result, and qualify "every result" in AC-35 and FR-043-AC-26. | spec/functional/FR-041-signed-tag-approval-of-a-change-assurance-record.md:104-112; FR-041-AC-35; FR-043-AC-26 |
| FND-003 | medium | "The command SHALL NOT judge any key at the local clock" is stated without qualification. On git before 2.35 the SSH path judges `valid-before` at verification time, which is the local clock. The same FR says so, and FR-037-AC-9 depends on it. Either scope the sentence to the gitsign certificate, or state that the SSH path delegates to git. | spec/functional/FR-041-signed-tag-approval-of-a-change-assurance-record.md:262; FR-037-AC-9 |
| FND-004 | low | FR-040-AC-14 allows "the already-present `sigstore-verify` crate used only for FR-041's trusted time". The binary already uses `sigstore-verify` for attestation and receipt verification, and the `signature-verify` and `approval-verify` features do not include it. As worded, the inspection cannot pass. Say "no new crate beyond `sigstore-verify`, already in the binary" and name the feature that adds it. | spec/functional/FR-040-gitsign-sigstore-keyless-commit-and-tag-verification.md:339; Cargo.toml:461-464,489,521 |

## Verdict

Not mergeable until FND-001..003 are fixed. All three are wording-level fixes in the same files. Cross-FR propagation of `trust` and the time members to FR-043 and FR-047 is otherwise consistent: FR-047-CON-3 is correctly narrowed to the release module, and FR-036-CON-2 / AC-12 correctly point to FR-037-CON-3 as the one hashing exception.
